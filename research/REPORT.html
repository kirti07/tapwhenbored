Tap When Bored, platform review

2026-09-05 · branch main at 90bf561 · Markdown source in REPORT.md

Short version. The site is healthy at 8 games and will hurt at 20. The cause is one thing repeated in different forms. Each game carries its own copy of the platform, so every platform change is eight edits.

The fix is two small shared modules and a handful of validator checks. Nothing changes a URL or adds a dependency.

Separately, the offline PWA spec at the end sets out how to make the installed app play every game offline and still pick up deploys: vite-plugin-pwa, one precache of the whole 190 kB catalogue, a 40-line register snippet.

Proposal

Architecture first, then UX. The UX items that matter most (mute, safe-area, modal end card, theme toggle) are shell problems. Done per game they are eight edits each and drift within a month. Done in the shell they are one edit and a test.

Offline PWA, spec

P items are decisions, not findings. Researched 2026-09-05 against vite-plugin-pwa 1.3.0, Workbox 7.4.1, Serwist 9.5.12, Playwright 1.62, Safari 26, Chrome stable.

Today the app is installable and nothing else. ARCHITECTURE §19 calls offline "a feature to add back on purpose". This is that. §41 lists "eager caching of all games" as something to avoid. The numbers below are the reason to overturn it, and §39 question 7 gets answered here rather than dodged.

The promise

  • 1
    Visit once, or add to the home screen, and every game plays offline from the next launch.Not only the games you happened to open.
  • 2
    A deploy reaches an installed app on its next launch.A game in play is never reloaded under the player.
  • 3
    Leaderboards and analytics still go to the network.They degrade as they do today (§20). Nothing about gameplay changes.

The whole playable site is about 190 kB gzipped. A game costs 3 to 6 kB of code, Word Steps 16 kB, plus a 1.3 kB document and a 1 to 5 kB thumbnail. Fifty games land near 700 kB, still less than one OG image. The old worker spent 276 lines and most of three architecture sections keeping install size proportional to games opened. At these sizes that scheme cost more than it saved.

  • P1
    Tool: vite-plugin-pwa in injectManifest mode.1.3.0 (May 2026) on Workbox 7.4.1 (May 2026), Vite 7 supported. Dev dependency only, nothing ships inside a page. The worker is our own ~25-line file importing workbox-precaching and workbox-core; the plugin bundles it into one self-contained /sw.js and injects the precache manifest at self.__WB_MANIFEST. Cost, said plainly: workbox-build pulls a large tree (Rollup, Babel) into node_modules, npm ci gets slower, dev deps go from 2 to 5, runtime stays at zero.
OptionVerdict
Hand-rolled worker, as beforeWhat got deleted was 276 lines of worker, 75 of register, 492 of tests, and most of the prose was about revisions, cache order and eviction. That is exactly what workbox-precaching does: revisioned manifest, atomic install, outdated-cache cleanup.
generateSW modeConfig only. Its defaults assume an SPA (navigateFallback to index.html) and it cannot express the one-off cleanup of legacy twb-* caches. We would spend the config fighting it.
Serwist (@serwist/vite)Maintained Workbox fork, 9.5.12 in July 2026, same API. Workbox shipped 7.4.0 in Nov 2025 and 7.4.1 in May 2026, so it is not stale. Pick the plugin with Vite as a first-class target. Serwist is the swap if Workbox stalls again; the worker code is the same either way.
  • P2
    One precache, filled atomically on install, diffed by revision on update.In: every document, everything under /static/, /assets/*-thumb.*, /fonts/*.woff2, /icons/*.png, the manifest and favicon. Out: *-og.jpg, sw.js, sitemap.xml, robots.txt, anything cross-origin. /static/ names are hashes so those carry no revision and no busting query (dontCacheBustURLsMatching: /^static\//); documents and public/ files get a content revision, so a thumbnail edit refetches one file. No runtime caching routes. A request not in the precache goes to the network untouched, which is what keeps the page.route leaderboard mocks in the smoke tests working.
  • P3
    Shared links and slashless URLs.ignoreURLParametersMatching: [/.*/] so /flip-it/?moves=12&size=5 hits the precached document. Four games read parameters from location.search, never from the document, so this is safe, and it was the old worker's cacheKey() lesson. urlManipulation adds a trailing-slash candidate so /honeycomb resolves offline the way Vercel's 308 resolves it online.
  • P4
    No offline fallback page.Every page is precached, so an offline miss is a URL that does not exist. Keep the browser's own error. navigateFallback stays off. This is an MPA, and answering a navigation with the homepage breaks gameplay and SEO.
  • P5
    Update flow.Worker calls skipWaiting() and clientsClaim() unconditionally. Safe in an MPA because a page never fetches its own modules twice and /static/ is immutable. It imposes one rule on games: load everything you play with before play begins. The lazy dictionary in U12 still gets imported at page load, off the critical path, or a mid-game update could remove the chunk it later asks for. /sw.js is served max-age=0, must-revalidate, Vercel's default, written into vercel.json explicitly so nobody widens a rule onto it.
deploy
  → next navigation, or registration.update() on resume
  → browser fetches /sw.js, byte-different
  → install: fetch only entries whose revision changed
  → skipWaiting
  → activate: cleanupOutdatedCaches, drop entries not in the manifest,
              delete legacy twb-* caches
  → clientsClaim
  → every open page receives controllerchange
  • P6
    The page-side snippet, scripts/sw-register.js, about 40 lines.Inlined into every page by the same plugin that inlines the theme bootstrap. Replaces scripts/sw-cleanup.js, which must go in the same commit because it unregisters every worker on every load. Registers after load. Records whether a controller existed before registering. On controllerchange reloads only when all three hold: homepage, a controller existed before, and the player has not touched the page (pointerdown, keydown, wheel, scroll). The new homepage is already precached, so that reload works offline. A game page never reloads. On visibilitychange to visible, calls registration.update() throttled to 15 minutes, because a resumed installed app never navigates. In display-mode: standalone, calls navigator.storage.persist(); Chrome grants it silently for installed apps, Firefox shows a prompt, hence the gate. injectRegister: null, no workbox-window: the homepage ships no JavaScript today and should not gain 3 kB of library for a 40-line job.

P7. Platform notes, verified September 2026

PlatformWhat holds
Chrome, Android and desktopInstallable without a worker since 108 and 112. Persistent storage auto-granted once installed.
iOS and iPadOS 26Anything added to the Home Screen now opens as a web app. The home-screen app has its own storage and its own days-of-use counter. ITP's 7-day script-storage purge applies to Safari tab use, and Apple says first-party data in home-screen apps is not expected to be deleted. Safari 17+ raised quota and added the Persistent Storage API.
iOS consequenceThe installed app registers the worker on its own first launch, since its storage is separate from the Safari tab. First launch needs the network. Second launch works offline.
PlaywrightService workers run in Chromium only. context.setOffline(true) works with a worker. page.route cannot intercept the worker's own script fetch, so the update test dispatches controllerchange synthetically, as the old suite did.
Dev serverNo worker in dev (devOptions.enabled: false). Different port from preview, so nothing leaks. Preview gets the real one and tests run there.

P9. Tests

All in tests/pwa/, Chromium, against preview.

  1. Every registry page registers and gets a controller.
  2. The precache holds every registry page, its /static/ files and its thumbnail, and holds no -og.jpg.
  3. setOffline(true), then open every game. The board renders and restart works.
  4. Offline, /flip-it/?moves=12&size=5 is served, and so is /honeycomb without the slash.
  5. Synthetic controllerchange. Untouched homepage reloads. After a pointerdown it does not. A game page does not. A first install does not.
  6. A leaderboard request still reaches the page.route mock with a worker live.
  7. visibilitychange calls registration.update() once, not twice within 15 minutes.
  8. storage.persist() is called in standalone and not in a tab, using the existing asInstalledApp() stub.

Manual, once per release that touches the worker: real iPhone and real Android. Install, kill the app, airplane mode, launch, play two games, check a deploy shows on the next launch.
